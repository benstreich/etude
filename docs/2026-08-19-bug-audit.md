## Release blockers

### 1. Metronome goes silent on Android when the screen locks or app backgrounds
`src/lib/metronome.tsx:139` + `modules/metronome-controls/.../MetronomeControlsModule.kt`
Beats are scheduled with JS `setTimeout`. RN's `JavaTimerManager.onHostPause()` freezes all JS
timers when the activity pauses (verified in RN 0.86 source), and the foreground service is a
plain `Service` — it keeps the process alive but not the timers. Clicking stops within one beat
of locking the phone while the notification claims it's still playing; the UI text promises
"Keeps playing with the app closed". **Fix:** run the beat loop natively in the existing service
(HandlerThread + SoundPool driven by the bpm/sig/ramp state JS already pushes via show/update);
JS clicks only while foregrounded. A HeadlessJS workaround is not reliable with the screen off.

### 2. Record button silently dead on every fresh Android 13+ install
`src/app/practice.tsx:100`
`setAudioModeAsync({ allowsBackgroundRecording: true })` makes expo-audio's
`prepareToRecordAsync()` throw `NotificationPermissionsException` whenever POST_NOTIFICATIONS
isn't runtime-granted (auto-granted only below API 33). The record flow never requests it and
`toggleRec` has no try/catch — the rejection is unhandled, nothing happens, no error shown.
The only requester is the metronome start path. **Fix:** in `toggleRec`, call expo-audio's
`requestNotificationPermissionsAsync()` first and pass its result as `allowsBackgroundRecording`
(recording still works foreground-only if denied); wrap prepare/record in try/catch + toast.

### 3. Starting the metronome or playing a recording mid-recording corrupts the take
`src/components/recordings.tsx:37` and `src/lib/metronome.tsx:151`
expo-audio's `setAudioModeAsync` does NOT merge — omitted flags reset to false. Both calls omit
`allowsBackgroundRecording`/`allowsRecording`, clobbering the mode set by the record flow.
Android: a live recording silently pauses on next backgrounding (UI keeps counting) and on stop
the "Recording audio" foreground notification is stranded permanently (unregister is skipped
when `useForegroundService` was flipped false). iOS: the live recorder is stopped outright the
moment the metronome starts. **Fix:** route all three `setAudioModeAsync` calls through one
helper that knows whether a recording is live and always merges the two recording flags.

### 4. Every fresh install ships fake demo data as the user's real data
`src/lib/store.tsx:72-120`
`seed()` is the design fixture: name "Alex Rivera", Piano/Guitar, 4 pieces, 2 sessions logged
"today", bestStreak 21, totalMin 86 h (inconsistent with minutesByDate's 197 min), a fully
practiced week chart. `migrate(null, seed())` hands it to every first install and it's
immediately persisted as real data. No UI can ever clear the fake bestStreak/totalMin.
**Fix:** neutral seed (name '', pieces/sessions/minutesByDate empty, bestStreak/totalMin 0),
keep all settings + metronome defaults so migrate's backfill still works. Demo fixture behind
`__DEV__` if still wanted.

### 5. A corrupt saved blob bricks the app into a permanent blank screen
`src/lib/migrate.ts:7` (called from `src/lib/store.tsx:172`)
`JSON.parse(raw)` unguarded; a `"null"` blob throws at `saved.stageLabels`, `{"pieces":null}`
throws at `merged.pieces.map`. The load effect has no catch; the rejection is silent, state
stays null, StoreProvider returns null forever — and the splash has already hidden. Every
launch re-reads the same blob: unrecoverable without wiping app data. **Fix:** try/catch in
`migrate()` returning `seedState` (guard non-object `saved` and non-array `pieces`); optionally
stash the bad blob under a backup key first.

### 6. The app ships with Expo's own branding as its identity
`app.json:7` (+ 16-18, 42-43, and `ios.icon`)
Launcher icon, adaptive icon foreground/monochrome, splash image (byte-identical to
expo-logo.png on Expo-blue), and the iOS icon bundle are all the unmodified Expo trademark.
Play can reject/take down under impersonation/IP policy. **Fix:** real Étude artwork for all
of them; remove or replace the `ios.icon` entry.

### 7. Enabling or editing the tempo ramp mid-run applies it retroactively from run start
`src/lib/metronome.tsx:130` (`setRamp` at 188-198)
Ramp is computed from anchors set at run start; only `setBpm` rebases them. Switch on
"+5 every 30 s → 120" ten minutes into a 60 BPM run and the next beat jumps straight to 120.
**Fix:** `setRamp()` rebases a live run exactly like `setBpm()` (baseBpm/baseBeats/startedAt).

## The stale-"today" family — one root cause, four user-visible bugs

With `reactCompiler: true`, zero-dependency render-body expressions are cached once per mount,
and the tab screens + StoreProvider stay mounted for the whole app session. There is no
AppState listener or midnight timer anywhere, so after any midnight crossing (app backgrounded
overnight — normal on Android) the app shows yesterday until the process dies:

8. **Today card ignores everything logged after midnight** — `store.tsx:262` freezes the
   `today` key; `logMinutes` writes to the new date while `todayMin` reads the old one, so
   fresh practice appears to vanish from the goal card. (high)
9. **Home header shows yesterday's date/greeting; old sessions stay labeled "Today"** —
   `index.tsx:48-49`, `dayLabel` at `index.tsx:97`. (medium)
10. **Progress "This week" drops earlier weekdays and "Avg / day" divides by a stale count** —
    `progress.tsx:20` (`elapsed` frozen at mount; verified by compiling the file with the
    project's own react-compiler). (medium)
11. **Log-past calendar disables today's cell after midnight** (compares against yesterday's
    key; month nav freezes at month boundary too) — `log-past.tsx:23`. (medium)

**Fix (one change):** hold `todayKey`/`now` as React state in StoreProvider, refreshed by an
AppState "active" listener plus a timer set for next midnight; derive `todayMin`, `week`,
`displayStreak` window from it and thread it into `dayLabel`/`dateLine`/`greeting`/log-past.

## Medium

12. **Lock-screen "Pause" removes the controls entirely** — toggle maps to `stop()` which
    calls `Controls.hide()`; resuming requires unlocking and reopening the app, and mid-run
    tempo nudges are discarded. `src/lib/metronome.tsx:162`. Fix: real `pause()` path that
    updates the notification (`running: false`) instead of hiding it.
13. **First-run Android 13+: lock-screen controls never appear even after granting** —
    notification is posted before the permission request; grants don't retroactively show it
    and nothing re-posts. `src/lib/metronome.tsx:154`. Fix: after the grant resolves, call
    `Controls.update(...)` if still running.
14. **START_STICKY resurrects a zombie, undismissable "120 BPM" notification with dead
    buttons after process death** — `MetronomeControlsModule.kt:67`. Fix: `START_NOT_STICKY`.
15. **Native recorder stops (notification Stop button, error, interruption) go unnoticed** —
    no `recordingStatusUpdate` listener; UI keeps "recording", saved duration is wall-clock,
    take silently truncated. `practice.tsx` (recorder at :30, duration at :66). Fix: pass a
    statusListener to `useAudioRecorder`; finalize on non-JS-initiated `isFinished`.
16. **Discarding a session leaks the whole audio file forever** — recorder writes to the
    documents dir (~1.9 MB/min); discard never deletes `recorder.uri`. `practice.tsx:187`.
    Fix: delete the file in discard (expo-file-system `File`, as recordings.tsx already does).
17. **iOS: saved recordings all break after every app update** — absolute `file://` URIs are
    persisted, but the iOS container UUID changes per update; playback silently fails and
    delete strands the real files. `store.tsx:280`. Fix: persist basename, resolve against
    `Paths.document` at use time, rewrite existing URIs in `migrate()`.
18. **Blank wrong-colored flash on every cold start** — splash hides when fonts load, but
    StoreProvider renders null until SQLite hydration. `_layout.tsx:45`. Fix: hide the splash
    from Shell's first mount/onLayout instead (Shell renders only after hydration).
19. **Keyboard covers the Settings edit sheet and Log-past minutes input** — the two sheets
    missed by commit 169a66c's KeyboardAvoidingView fix; profile's input even autofocuses.
    `profile.tsx:163-304`, `log-past.tsx:143-151`. Fix: same KAV wrapper as practice.tsx:262.
20. **Duplicate piece names double all stats and recordings** — identity is the display name
    everywhere (session titles, recording joins, chip keys; piece named like a technique also
    collides React keys). `repertoire.tsx:105-113`, `store.tsx:228-233`. Fix: case-insensitive
    dupe check in `addPiece` (+ key chips by `kind:name`).
21. **Deleting/archiving a piece or technique leaves it as the standing quick-log target** —
    sessions keep getting attributed to a ghost piece. `store.tsx:267` (+ 243, 272). Fix:
    clear matching `quickLogFocus` in remove/archive.
22. **All 7 days selectable as break days** → streak never breaks (May + August = "2-day
    streak", permanently baked into bestStreak) and every compute runs 3650 `toLocaleDateString`
    calls (twice per log). `streak-math.ts:31`, `profile.tsx:64`. Fix: cap selection at 6;
    replace `dayName` with a static `NAMES[d.getDay()]` lookup; add the case to check-streak.

## Low (confirmed)

23. **bestStreak never counts streaks assembled purely from backdated logs** — computeStreak
    only measures the streak touching today. `store.tsx:198`. Fix: a full-history
    `computeBestStreak` helper in streak-math (anchor at each run end, take max).
24. **Persistence failures are silently swallowed** — `Storage.setItem` promise ignored; on a
    full disk the app keeps toasting "Saved" while nothing persists. `store.tsx:178`. Fix:
    `.catch(() => setToast('Save failed — device storage may be full'))`.
