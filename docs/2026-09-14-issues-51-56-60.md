## The thing you need to know first

**The iOS half of `modules/pdf-pages` has never been compiled.** It is PDFKit code
written without an Apple account to build against, the same caveat
`modules/pitch-input` already carries in its header. The Android half is
`PdfRenderer` and is equally unrun on a device. Everything else here is JavaScript
and was verified in a browser (see *How this was verified*).

The first EAS build after this commit is the real test. If `PdfPages` fails to
register, PDF import degrades to the "PDFs need the full app build" toast rather
than crashing — `requireOptionalNativeModule`, same pattern as the widgets and
tuner modules — so a broken native side is survivable, not silent.

### #56 — weekly, monthly and yearly goals; per-piece deadlines

| Area | Files | What |
|---|---|---|
| The maths | `src/lib/goal-math.ts` (new), `scripts/check-goal.ts` (new) | `periodRange`, `periodMinutes`, `practiceDays`, `goalProgress`, `daysUntil`, `deadlineStatus`. Pure and node-runnable, like every other `*-math` module |
| Settings | `src/app/profile.tsx`, `src/lib/store.tsx` | A "Weekly · monthly · yearly" row and a three-input sheet. New flat settings `weeklyGoal` / `monthlyGoal` / `yearlyGoal`, seeded `0` |
| Progress | `src/app/progress.tsx` | A goals card (done vs. target, ahead/behind the straight-line pace) and a "coming up" list of unfinished deadlines, nearest first |
| Piece page | `src/app/piece/[id].tsx`, `src/lib/store.tsx` | `Piece.targetDate`, a "Mastered by" card with a Mastered / On track / Behind badge |
| Shared calendar | `src/components/calendar.tsx` (new), `src/components/log-past.tsx` | The month grid moved out of log-past and took a `direction: 'past' \| 'future'` prop. log-past lost ~60 lines |

**A period goal of `0` means "derive from the daily goal"** — daily × the practice
days in the period, break days excluded. One branch instead of a second "auto" flag,
and the derived number stays correct when the daily goal or the break days change.
Settings shows derived values with a `*`, e.g. `120* · 520* · 6260* min`.

No date-picker dependency was added. Extracting the existing grid was smaller than
installing one, and it made log-past shorter rather than longer.

### #60 — attach a score or image to a piece

| Area | Files | What |
|---|---|---|
| PDF rasteriser | `modules/pdf-pages/` (new) | `render(uri, outDir, maxWidth) → RenderedPage[]`. PDFKit on iOS, `PdfRenderer` on Android, both writing `1.png`, `2.png`, … and both painting white paper first |
| Model | `src/lib/attachment-math.ts` (new), `scripts/check-attachment.ts` (new) | `Attachment { id, piece, name, kind, files[], addedAt }`, the mime/extension kind rule, path naming, per-piece grouping |
| Disk | `src/lib/attachments.ts` (new), `src/lib/doc-path.ts` (new) | Picking, copying into `attachments/<id>/`, deleting a folder |
| Store | `src/lib/store.tsx`, `src/lib/migrate.ts` | `attachments` array, add/rename/delete, and `removePiece` deleting the folders |
| UI | `src/components/score.tsx` (new), `src/app/piece/[id].tsx`, `src/app/practice.tsx` | Score card on the piece page, Score pill over the running session, full-screen pager with pinch-zoom |
| Root | `src/app/_layout.tsx` | `GestureHandlerRootView` — the app had `react-native-gesture-handler` as a dependency but had never mounted the root view |
| Backups | `src/lib/backup.ts`, `src/app/profile.tsx` | `exportBackup` takes documents-relative paths instead of recordings, so score pages ride along in the same base64 map |

**PDFs are rasterised once, at import.** The viewer is then a single code path —
images — and never opens a document. That was a deliberate choice over a WebView +
pdf.js (one new dependency, ~1 MB of bundled JS, two code paths) and over handing
PDFs to the OS viewer (leaves the app, which the issue forbids).

**Files persist documents-relative**, resolved at use time. Same rule recordings
adopted in the #17 bug audit, for the same reason: iOS changes the app container
UUID on every update, so an absolute URI rots.

**The backup question the issue left open is settled: no zip.** Recordings were
already embedded as base64 in one JSON file; score pages now go in the same map.
`restoreFiles` already created intermediate directories for arbitrary relative
paths, so restore needed no changes at all.

## Gotchas & notes

- **`store.tsx` imported `attachments.ts` which imported `store.tsx` back.** The
  fix was pulling `toStoredUri` / `resolveRecordingUri` into `src/lib/doc-path.ts`
  and re-exporting them from the store, so existing callers are untouched. Metro
  tolerates cycles; it was not worth finding out when.
- **Attachment folders are keyed by attachment id, not piece.** Ids are already
  filesystem-safe, so no name sanitising and no rename bookkeeping. Deleting one
  attachment is deleting one folder.
- **The app has no danger colour.** Destructive actions are `C.accent` —
  `recordings.tsx` does the same. There is no red in the palette.
- **The Playwright MCP server holds a browser-profile lock** and refuses a second
  instance, exactly as the prior handoff warned. A standalone script with its own
  `playwright` install sidesteps it — installed in the **scratchpad**, never the
  repo, which is the mistake the same handoff records.
- **Tab-bar clicks by coordinate do not navigate** in the web build. Use expo-router
  URLs directly (`/repertoire`, `/progress`, `/profile`, `/piece/<id>`).
- **Screenshots live in the session scratchpad and are not in the repo.**

## How this was verified

```bash
npm run check        # 16 suites, all print ok — includes new check:goal, check:attachment
npm run check:i18n   # i18n ok — 531 keys, 437 static usages checked
npx tsc --noEmit     # silent
npm run lint         # 1 pre-existing warning in src/lib/reminders.ts, 0 errors
```

Both bundles build, which is what proves the new imports resolve on native as well
as web (the local module has a `.web.ts` stub, so web alone would not prove it):

```bash
npx expo start --web --port 8099
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" \
  "http://localhost:8099/node_modules/expo-router/entry.bundle?platform=android&dev=true"
# 200 6600788
```

The UI was driven in a headless browser through onboarding → add a piece → piece
page → target-date sheet → Progress → Settings. The goals arithmetic was checked
against the rendered numbers: daily goal 20, Sundays off, on Monday 14 September
2026 — week target 120 (6 × 20), month target 520 (26 × 20), month pace 240 after
12 elapsed practice days, so "210 min behind pace" with 30 logged. It matches.

**Not verified:** anything native. No PDF has been rasterised, no attachment has
been written to disk, and the `Directory` / `File` copy calls in `attachments.ts`
have only ever run against the web stubs.
