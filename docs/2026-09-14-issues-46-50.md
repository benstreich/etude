## The thing you need to know first

**Trimming a recording does not cut the file.** Recordings are AAC in an MP4
container (`RecordingPresets.HIGH_QUALITY` → `.m4a`) and nothing in the JS
runtime can decode or re-encode that. ffmpeg-kit is retired and there is no
maintained Expo-compatible replacement in the dependency set.

So `start` / `end` / `loop` on `Recording` are **playback bounds**, not edits.
The row shows the trimmed duration, playback starts at the in point and stops
(or loops) at the out point, but the file keeps its full audio — which means
**export shares the untrimmed take**. That is the one place the illusion leaks,
and it is flagged in a `ponytail:` comment on `share()` in
`src/components/recordings.tsx`.

The trim maths is extracted to `src/lib/trim-math.ts` so
`scripts/check-trim.ts` can exercise the handle clamping without a device.

## #48 was a double-lift, not a missing avoider

Worth writing down because the previous session fixed the *opposite* bug (#39)
and the fix is what caused this one.

Android resizes the window when the keyboard opens. `SHEET_AVOID` was
`'padding'`, so `KeyboardAvoidingView` added a second keyboard's height on top
of that: sheet titles ran under the status bar with a band of dead space above
the keys. Expo's keyboard-handling guide says to use `behavior={undefined}` on
Android — keeping the KAV still pulls the focused input into view. iOS windows
genuinely don't resize, so iOS keeps the padding.

```ts
export const SHEET_AVOID = Platform.OS === 'ios' ? ('padding' as const) : undefined;
```

One constant in `src/components/ui.tsx`, and it covers every sheet at once:
profile, piece, plan, repertoire, edit-session.

If a sheet now sits *under* the keyboard instead, the fix is a `maxHeight` on
the sheet, **not** restoring the padding. `edit-session.tsx` hard-codes
`height: winH - insets.top - 12`, which is the one most likely to misbehave.

## The time wheel is deliberately not native

`@expo/ui` is in `package.json` and ships a real `DateTimePicker`, but its
native pickers need a dev build. The reminder setting has to keep working in
Expo Go, so `src/components/time-wheel.tsx` is two snapping `ScrollView`s plus
an AM/PM toggle. ~80 lines, no new dependency.

Related, and the actual reason the issue was filed: **once Android's
notification prompt is denied it never asks again.** `requestPermissionsAsync`
returns denied silently, so the reminder scheduled nothing and the user only
got a start-up toast. There is now a tappable "notifications are off" line in
the reminder sheet that calls `Linking.openSettings()`, gated on
`notificationsAllowed()` in `src/lib/reminders.ts`.

## Technique recordings

They used to fall into an orphan block at the bottom of Repertoire, because
`Recording.piece` holds the focus name and only pieces had rows. Technique rows
now carry the same expandable recordings list, keyed `tech:<name>` so the key
can't collide with a piece id. The bottom block survives but is now genuinely
"other" — recordings whose piece or technique no longer exists — and its label
changed to match.

## #50 — what the sweep found

Fixed in `1ff1c84`:

1. **Discard left Android in record mode.** `endRec` and the start-failure path
   both call `applyAudioMode({ playsInSilentMode: true })` to leave
   communication routing; the discard path cleared the recording flags and
   forgot. Bluetooth A2DP stayed muted and the metronome played at call volume.
2. **Editing the stage list left `pct` on the old scale.** `updateSettings`
   clamped the stage index but not the percentage, so 3→4 stages showed a
   "Polishing" piece at 100%. The formula existed in three copies; it is now
   `stagePct()` in `src/lib/stage-math.ts` with `scripts/check-stage.ts`.
3. **`addTechnique` deduped case-sensitively and untrimmed**, unlike
   `addPiece`. The name is the join key for sessions and recordings, so
   "scales" beside "Scales" silently splits that technique's stats.
4. **Practice focus matched on name only**, so a piece and a technique sharing
   a name both highlighted.

confirm the sheet sits directly on the keyboard; open Settings → Reminders for
the wheel; trim a recording on its waveform and play it back; open Progress and
check the month header is centred.
