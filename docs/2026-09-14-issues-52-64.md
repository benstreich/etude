## #52 was the wrong screen twice

The issue screenshot showed a calendar where the selected day is a box and today
is a circle. Progress has a calendar too, and it was the wrong one — the fix
lives in `src/components/log-past.tsx`, the Log-past-practice sheet.

Cause, worth remembering: `r(n)` scales border radius by the user's Corners
setting, and `r(17)` on a 34px cell is only a circle at 100%. `r(999)` is the
pill escape hatch and is not scaled, so the day stays round whatever the setting.

Downloading an issue image needs the auth header:
`curl -H "Authorization: token $(gh auth token)" <url>`.

## #53: the double cue is guarded, not cured

The session-complete sound fired twice and I could not reproduce the cause — the
review effect fires twice under some remount I never pinned down. The fix is a
3-second window in `playSessionComplete` (`src/lib/sounds.ts`): one cue per
3s, whatever the caller does. It is a sink-side guard and the comment says so.
If a future caller legitimately needs two cues back to back, that window is what
will bite.

The instrument half is `src/lib/cue-voice.ts`: instrument name → one of four
timbres (`mallet` / `pluck` / `bow` / `perc`), keyword rules in order so
"Bass Clarinet" matches bow before "bass guitar" can claim it. All four cue
samples are the same D4→G4 motif from `scripts/make-cues.py`, so the app still
sounds like one app. `scripts/check-cue-voice.ts` asserts the overlapping names
and that all 92 instruments land on a sample that exists.

`primaryInstrument` in the store picks which one voices the cue when several are
listed.

## #57: one scale, three runtimes

Accents are a 0–3 `Level` (muted / plain / mid / accent) and that scale is
duplicated in three places by necessity — `src/lib/metronome-math.ts`, the JS
sound pool in `src/lib/metronome.tsx`, and `SOUND_SETS` in
`MetronomeControlsModule.kt`. The sample order (beat, mid, accent, sub) is the
contract between them. Add a sound set on one side only and the other two go
silently wrong; there is no check that can catch it across the language
boundary.

`metroAccents: []` means "whatever the signature implies" — `fitAccents` derives
the pattern from the time signature and only stored non-empty arrays override
it. Changing the signature clears the array on purpose, because a 4-beat pattern
in 3/4 is not something the user asked for.

`scripts/make-click.py` was rewritten to generate all five sets × four levels.
It had gone stale: regenerating the old version would have silently undone
`3e5fe8f` (#35, hand-boosted click peaks). The LEVELS table now carries peak
*targets*, so the script reproduces the shipped loudness — verified wood matches
the committed sample to within 2/32767. Rebuilds are byte-identical because the
noise is seeded from the frequency.

The browser session caught a real bug the reasoning did not: the subdivision
segmented control ran off the right edge at 420px once German labels landed
("2 pro Schlag" × 4). Equal-width cells and bare counts now, with the unit in a
hint line — `c97a36e`.

## Working in a tree another agent is editing

`git add <shared file>` sweeps up the other session's uncommitted edits. It
happened once (`d292df2` carries their Stars work) and the way to avoid it is to
stage from HEAD instead of from the working tree:

```
git show HEAD:path > tmp      # their edits are not in HEAD
<apply only your edits to tmp>
git hash-object -w tmp        # → sha
git update-index --cacheinfo 100644,<sha>,path
```

`git apply --cached --3way` of filtered hunks does *not* work — the working-tree
context contains their additions and the patch is rejected. And capture git
output as bytes and `.decode("utf-8")`: `subprocess.run(text=True)` decodes as
cp1252 on this machine and turns every em dash into mojibake.
